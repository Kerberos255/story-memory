# 剧情记忆 · Story Memory

轻量 SillyTavern 剧情记忆扩展：楼层摘要、章节与长期概览，配套物品、场景、角色状态，以及按需向量召回。

## 安装

在 SillyTavern → 扩展 → 安装扩展，输入：

```text
https://github.com/Kerberos255/story-memory
```

刷新酒馆，在输入框上方点击「✦ 剧情记忆」打开弹窗。默认暗色主题，可在右上角切换明亮主题。

## 功能

- **摘要**：按剧情楼层整理事件和状态，并生成阶段总结、二次总结及长期剧情概览；长篇章节与楼层列表分批加载，剧情时间线支持按楼层、时间、地点和正文搜索。卡片单独标注已保存的故事时间与地点；旧摘要没有独立时间字段时，仅从摘要正文开头明确出现的时间回显，不猜测年份或修改已保存内容。可以调整整理频率，摘要可查看来源、编辑或删除。
- **物品 / 场景 / 角色**：从剧情中提取实际变化，沿用已登记人物和物品的身份；同一个对象换称呼不会默认新建记录。记录的变更历史与字段生效/失效楼层按已有 Delta 推导，可查看原文证据和证据缺失提醒；已移除实体会显示在归档视图，不重新注入为当前状态。当前实体卡提供折叠的「人工纠错」，保存后优先采用手动确认的状态，但后续剧情明确更改相同字段时，旧纠错会失效并提示核对；可恢复自动提取值，且不修改原始摘要。对确认为同一实体的重复名称，可在对应页面手动合并或撤销，不自动猜测相似名称。再次声明新增同名实体、或同名对象被引用了冲突的实体 ID 时，会保留原状态并在折叠区域提示人工核对，而不是自动覆盖。
- **计划与伏笔**：独立页面显示任务、约定和伏笔，支持手动添加及合并不同称呼；是否注入可以独立设置。当计划记录之后存在尚未摘要的剧情（包括最新的玩家消息）时，插件仅按楼层先后判断其状态可能过期，将计划保留为「历史计划／状态待核对」，不再把原来的未完成状态当作当前待办；不依赖关键词匹配，也不推测是否已经完成。已经确认完成或取消的计划不会重新成为待办。待新楼层摘要更新后恢复准确状态。关闭某项注入不会停止提取或清除历史，剧情摘要仍默认发送给主模型。
- **摘要 API**：默认「跟随主 API」，也可选择「独立副 API」。独立模式可在插件内填写 URL、API Key、模型，并通过模型旁的刷新按钮获取模型列表。跟随模式使用酒馆当前模型和 `generateRaw`；独立模式通过酒馆 Custom API 服务端代理发送请求，**不会修改主 API 设置**。
- **附加参数**：折叠收纳「包含主体参数 / 排除主体参数 / 包含请求标头」。支持每行 `名称: 值`，包含主体参数也接受 JSON 对象；插件不替你填写任何服务商标头。
- **提示配置**：L0 的「提取物品／场景／人物／计划」四个独立开关默认开启；关闭后不再给摘要 API 发送对应的默认提取指令和既有实体对照表，返回结果入库前也会过滤该类别。旧实体档案不删除，仍可由「记忆发送」单独控制是否交给主模型；剧情摘要照常描述相关事件。L0 默认提示词按开关组装，完整自定义提示词原文保持不变，程序在请求末尾附加固定 JSON 协议；「预览最终提示词」可以查看当前开关与编辑草稿组合的实际 L0 系统指令，不请求 API。L1、L2、L3+ 仍做自然语言剧情压缩，不因关闭实体提取而删除重要剧情信息。
- **默认提示词优化**：L0 更严格区分本轮事实、回忆、承诺与状态变化，优先凭证据维护实体身份，避免同名误合并或重开已完成事项；L1 按关键结果、持续状态和未解决事项决定章节取舍；L2 记录跨章节的前态→转折→后态；L3+ 保留长期主线及有延续影响的结局。固定 JSON 协议采用空白结构和动态字段说明，不再给模型可能被误抄的虚构实体示例。已保存的自定义提示词不会被这些默认文案覆盖。
- **历史检索**：默认自动寻找相关旧剧情；不配置任何向量 API 也能搜索关键词、人物、物品与事件，并沿章节来源找到原始楼层。每轮默认最多参考 5 条记忆、补充 3 处原文，可在「记忆检索 → 历史检索」调整或关闭。摘要页的「查看原文」可直接查看来源；切换回复、编辑或删除原文后，对应旧来源自动失效。历史正文若已被真正删除，无法凭空恢复；自动检索不额外请求 LLM。
- **语义检索＋重排**：Embedding 默认 `BAAI/bge-m3`，重排默认模型 `BAAI/bge-reranker-v2-m3`（**重排开关默认关闭**，需自行开启；在「记忆检索 → 语义检索」开启即可自动检索并发送给主模型）。向量模型配置默认折叠；Embedding 和重排共用独立向量 API 的 URL／Key，分别请求 `/embeddings` 和 `/rerank`；重排最多选取 2–30 条候选（默认 15），在向量 Top-K 输出前重新排序，失败时回退向量排序，不阻断主模型。重排需要服务商提供兼容的接口。与酒馆主 API 和密钥隔离；**浏览器直连要求 CORS**。向量索引缓存在 IndexedDB，可从聊天摘要重建；同一聊天短时间重复召回复用缓存，Top-K 使用固定长度候选集合以降低分配与排序开销，仍需对当前记忆做来源有效性核对。Key 存于扩展设置，不要公开含配置的备份。
- **记忆发送**：剧情摘要及人工剧情记忆默认参与注入，无需单独开关；「记忆发送」只控制物品、场景、角色、计划四类实体记忆。历史与语义检索在「记忆检索」中分别开启后，自动检索并注入相关结果，无需再次设置。旧版隐藏的检索注入开关不再生效。注入时优先保障剧情主线，不截断单条事实。记忆作为**历史背景**注入到 Chat History 的最前端，不穿插最近的 user/AI 回合；明确标记旧记忆，若与更新的实际聊天冲突则以后者为准。注意：和其他聊天内容一样，如果上下文空间不足，位于最前端的记忆也可能被酒馆裁剪。预览可在当前草稿模拟与上轮生成时本扩展设置给酒馆的提示词之间切换（不包括其他预设及插件）；Token 由酒馆当前配置的分词器统计（分词器与实际模型不同时仍可能存在偏差），字符数按 Unicode 码点统计；酒馆接口不可用时回退为字符长度估算并明确标记。正式生成前用酒馆统计结果检查记忆 Token 预算，超出则减少完整记忆条目，不截断 JSON；预览下方折叠「记忆组成」列出各区字符数与跳过条目数。

## 摘要设置

- 默认温度 `0`。「Think 等级」提供 Auto（默认）、Low、Medium、High、Max 下拉选项：独立摘要 API 手动选级时通过 Custom 请求的 `reasoning_effort` 指定，Auto 不添加思考参数；是否支持具体级别取决于模型，若报不兼容请改回 Auto。跟随主 API 时沿用酒馆本身的思考设置，不由插件单独覆盖。独立摘要 API 的「输出上限（可选）」默认留空，不主动设置 `max_tokens`，采用服务商默认值；需要时填入明确的 Tokens 数。部分模型不接受温度 0，或默认输出较短导致 JSON 不完整，可根据实际模型调整。
- **自动摘要**默认开启（已保存的关闭设置仍保留）；**延迟自动摘要**默认 `3`，表示最新 3 条 AI 回复不会自动摘要，第四条 AI 回复到来后才开始整理更早楼层。按 AI 楼计算，不包含用户消息。每次 AI 回复结束后最多自动补处理 `5` 条待摘要楼层，防止旧聊天集中请求 API；手动批量补摘不受延迟及此上限限制。
- **JSON 输出保护**：L0 摘要必须返回恰好一个可校验的 JSON 对象；多对象输出直接拒绝，其他可修复的格式异常最多额外请求一次进行格式修复，仍失败则保留错误状态而不覆盖旧记忆。使用自定义提示词时，关闭的实体类别同样会在保存前过滤；格式修复可能增加一次 API 请求与相应 Token 消耗。
- **摘要成功后自动隐藏楼层**默认开启（已保存的旧设置不被覆盖）。只隐藏摘要有效、已离开保留窗口的 AI 楼层及其连续关联用户输入；不删除原始聊天。**保留最近正文**默认 `3`，与自动摘要延迟数取较大者保护最新剧情。长篇楼层必须完整处理并保存后才能自动隐藏；缺少完整覆盖证明的旧摘要会保守处理。
- 自动隐藏采用 SillyTavern `/hide` 同等的 `is_system` 消息可见性机制。编辑、切换 Swipe 或删楼后，插件会取消受影响的在途摘要任务并恢复失效来源对应的隐藏消息；当前运行会话删除中间楼层时，会利用消息对象身份重绑定未变化的摘要与分层来源，无法确认的记录失效待补摘。关闭自动隐藏不会自动恢复此前已隐藏的消息；如需手动恢复，在酒馆使用 `/unhide`。
- 分层压缩默认：L0→L1 阈值 `12`，保留最近 `3` 条未压缩 L0 摘要；L1→L2 阈值 `6`，L2→L3 及之后每级阈值 `3`。阈值设为 `0` 可关闭对应压缩层级。
- **楼层实体更新**：每楼层摘要同时提取物品、场景、角色、计划的变化；在摘要卡片展开后可看到本楼层提取数量。默认提示词会登记首次出现的重要实体，同时兼容模型将变更字段放进 `delta` 或 `entities` 的 JSON。已有自定义提示词不会被覆盖。手动逐楼补摘与自动摘要使用同一套提取流程；已摘要楼层不会自动重复提取。
- **长剧情自动整理**：不再提供「单楼层原文上限」输入框；超过单次请求适宜长度的剧情会按原文顺序自动分段、逐段提取物品／场景／角色，再合并摘要。中途失败不会保存半截楼层，重新补摘仍可重试。明确遇到请求过大或上下文超限时，会自动缩小相关分段；其他 API 错误正常反馈。极端超长楼层仍可能需要拆成多个楼层；分段会增加模型请求次数。既有单楼层原文长度设置在新版本不再生效。
- **摘要防错**：默认提示词强调用户行动→角色反应→结果，事实与角色说法、怀疑、计划分开；结构化更新尽量携带当前楼层的连续原文 `evidence`。引用了不存在的原句的变更会被忽略，无引文的旧条目不会被冒充为已核验。明确失效的单个字段可用带本轮证据的 `clear_fields` 退休，未填写字段不会视为删除；历史版本仍可查阅。长篇章节总结也会自动分批合并，不会截掉原始素材。
- **角色知情与在场**：在原有角色实体中保存 `knowledge` 增量条目，包含 `fact`、`stance`（knows/suspects/believes/hides）、原文证据和可选 `provenance`（firsthand / secondhand / unknown）；仅有明确证据才能增删。新默认提示词在原文明示人物在场或离场时可记录 `presence`（present / absent），注入时压缩不在场人物的地点与详细说明，但保留必要身份、关系和已知信息；未经确认的在场状态视为未知。已有自定义提示词不会被覆盖。

## 时间与摘要修改

- 有完整日期的故事时间可规范为 `YYYY/MM/DD HH:mm`；只有月日没有年份时，原样保留「三月十二日清晨八点十五分」，不补造年份。旧记录在时间线显示时也尝试规范格式，不改写原始聊天文本。
- 摘要和分层总结卡片展开后显示**一份摘要正文**，底部有「查看原文」「编辑」「删除」按钮。点击编辑弹出独立居中窗口（L0 可编辑正文、故事时间、地点；L1+ 只编辑正文）；点击删除弹出单独的二次确认窗口，明确影响范围。按 Esc、点击外部遮罩或「取消」只关闭当前操作窗口，不关闭整个剧情记忆插件，未保存的草稿不会改动记忆。
- L0 摘要支持修改正文、故事时间与地点；L1/L2/L3+ 总结支持修改正文。修改时会使依赖旧内容的高层总结失效，但不会覆盖原始聊天。
- 删除生成的楼层摘要会同时撤销该楼层提取的物品、场景、人物、计划变化，保留原始聊天，并暂停对当前版本楼层的自动重新摘要。摘要页提供「重新摘要」入口；原剧情改变时可重新进入待摘要列表。
- 删除 L1+ 分层总结时保留下层素材，且避免同一批素材立即重复压缩。删除操作需确认。
- **恢复默认**：重置 Embedding 模型为 `BAAI/bge-m3`、重排模型为 `BAAI/bge-reranker-v2-m3`，重排开关关闭，保留向量 API 地址与密钥；摘要 API 的连接配置与模型照旧保留。

## 配置示例

附加参数 → 包含主体参数：

```text
prefix: true
```

附加参数 → 排除主体参数：

```text
frequency_penalty
presence_penalty
```

附加参数 → 包含请求标头：

```text
x-example-session: demo
```

以上标头只是普通格式示例，不会自动填写。Authorization、Cookie 等认证标头不能手动添加；独立摘要 API 自动使用该渠道填写的 Key。**独立摘要 Key 会保存在 SillyTavern 扩展设置中**，请勿公开导出包含扩展设置的备份。

## 使用提示

自动摘要与自动隐藏均默认开启，但仅在成功摘要且离开保留窗口后才会隐藏旧正文。首次使用建议先在测试聊天验证副 API 响应格式、记忆注入与自动隐藏，再对长期聊天启用批量整理。

自动隐藏需要酒馆提供保存聊天的接口，实际效果仍需在目标酒馆版本测试。启用前建议先检查「预览发送内容」；旧聊天原文未隐藏时可能与记忆注入重复。上游内容拒绝不会通过反复重试绕过。
