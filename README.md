# 剧情记忆 · Story Memory

轻量 SillyTavern 剧情记忆扩展：楼层摘要、章节与长期概览，配套物品、场景、角色状态，以及按需向量召回。

## 安装

在 SillyTavern → 扩展 → 安装扩展，输入：

```text
https://github.com/Kerberos255/story-memory
```

刷新酒馆，在输入框上方点击「✦ 剧情记忆」打开弹窗。默认暗色主题，可在右上角切换明亮主题。

## 功能

- **摘要**：按剧情楼层整理事件和状态，并生成阶段总结、二次总结及长期剧情概览。可以调整整理频率，摘要可查看来源、编辑或删除。
- **物品 / 场景 / 角色**：从剧情中提取实际变化，沿用已登记人物和物品的身份；同一个对象换称呼不会默认新建记录。对确认为同一实体的重复名称，可在对应页面手动合并或撤销，不自动猜测相似名称。
- **计划与伏笔**：独立页面显示任务、约定和伏笔，支持手动添加及合并不同称呼；是否注入可以独立设置。关闭某项注入不会停止提取或清除历史，剧情摘要仍默认发送给主模型。
- **摘要 API**：默认「跟随主 API」，也可选择「独立副 API」。独立模式可在插件内填写 URL、API Key、模型，并通过模型旁的刷新按钮获取模型列表。跟随模式使用酒馆当前模型和 `generateRaw`；独立模式通过酒馆 Custom API 服务端代理发送请求，**不会修改主 API 设置**。
- **附加参数**：折叠收纳「包含主体参数 / 排除主体参数 / 包含请求标头」。支持每行 `名称: 值`，包含主体参数也接受 JSON 对象；插件不替你填写任何服务商标头。
- **自定义提示词**：楼层摘要及物品／场景／角色／计划联合提取、L1 首次总结、L2 二次总结、L3+ 高层总结各自可查看全文、编辑或恢复默认。联合提取使用同一套结果，避免状态相互矛盾。
- **历史检索**：默认自动寻找相关旧剧情；不配置任何向量 API 也能搜索关键词、人物、物品与事件，并沿章节来源找到原始楼层。每轮默认最多参考 5 条记忆、补充 3 处原文，可在「历史检索」调整或关闭。摘要页的「查看原文」可直接查看来源；切换回复、编辑或删除原文后，对应旧来源自动失效。历史正文若已被真正删除，无法凭空恢复；自动检索不额外请求 LLM。
- **向量记忆＋重排**：Embedding 默认 `BAAI/bge-m3`，重排默认模型 `BAAI/bge-reranker-v2-m3`（**重排开关默认关闭**，需自行开启；还须启用「向量检索」及「注入设置 → 向量召回」）。共用独立向量 API 的 URL／Key，分别请求 `/embeddings` 和 `/rerank`；重排最多选取 2–30 条候选（默认 15），在向量 Top-K 输出前重新排序，失败时回退向量排序，不阻断主模型。重排需要服务商提供兼容的接口。与酒馆主 API 和密钥隔离；**浏览器直连要求 CORS**。向量索引缓存在 IndexedDB，可从聊天摘要重建，Key 存于扩展设置，不要公开含配置的备份。
- **记忆注入**：剧情摘要及人工剧情记忆默认参与注入，无需单独开关；物品、场景、角色、计划、相关历史和向量召回可独立启停。按预算选择完整记忆，不截断单条事实。注入预览在设置页弹窗中打开，关闭后保留当前设置草稿。Token 预算是近似估算。

## 摘要设置

- 默认温度 `0`。独立摘要 API 的「输出上限（可选）」默认留空，不主动设置 `max_tokens`，采用服务商默认值；需要时可以填入明确的 Tokens 数。跟随酒馆主 API 时不覆盖酒馆的响应长度设置。部分模型不接受温度 0，或默认输出较短导致 JSON 不完整，可根据实际模型调整。
- **自动摘要**默认开启（已保存的关闭设置仍保留）；**延迟自动摘要**默认 `3`，表示最新 3 条 AI 回复不会自动摘要，第四条 AI 回复到来后才开始整理更早楼层。按 AI 楼计算，不包含用户消息。每次 AI 回复结束后最多自动补处理 `5` 条待摘要楼层，防止旧聊天集中请求 API；手动批量补摘不受延迟及此上限限制。
- **摘要成功后自动隐藏楼层**默认开启（已保存的旧设置不被覆盖）。只隐藏摘要有效、已离开保留窗口的 AI 楼层及其连续关联用户输入；不删除原始聊天。**保留最近正文**默认 `3`，与自动摘要延迟数取较大者保护最新剧情。长篇楼层必须完整处理并保存后才能自动隐藏；缺少完整覆盖证明的旧摘要会保守处理。
- 自动隐藏采用 SillyTavern `/hide` 同等的 `is_system` 消息可见性机制，编辑用户内容或切换 AI swipe 后，旧摘要会失效，并尝试恢复被本插件隐藏的关联消息。关闭自动隐藏不会自动恢复此前已隐藏的消息；如需手动恢复，在酒馆使用 `/unhide`。
- 分层压缩默认：L0→L1 阈值 `12`，保留最近 `3` 条未压缩 L0 摘要；L1→L2 阈值 `6`，L2→L3 及之后每级阈值 `3`。阈值设为 `0` 可关闭对应压缩层级。
- **楼层实体更新**：每楼层摘要同时提取物品、场景、角色、计划的变化；在摘要卡片展开后可看到本楼层提取数量。默认提示词会登记首次出现的重要实体，同时兼容模型将变更字段放进 `delta` 或 `entities` 的 JSON。已有自定义提示词不会被覆盖。手动逐楼补摘与自动摘要使用同一套提取流程；已摘要楼层不会自动重复提取。
- **长剧情自动整理**：不再提供「单楼层原文上限」输入框；超过单次请求适宜长度的剧情会按原文顺序自动分段、逐段提取物品／场景／角色，再合并摘要。中途失败不会保存半截楼层，重新补摘仍可重试。明确遇到请求过大或上下文超限时，会自动缩小相关分段；其他 API 错误正常反馈。极端超长楼层仍可能需要拆成多个楼层；分段会增加模型请求次数。既有单楼层原文长度设置在新版本不再生效。
- **摘要防错**：默认提示词强调用户行动→角色反应→结果，事实与角色说法、怀疑、计划分开；结构化更新尽量携带当前楼层的连续原文 `evidence`。引用了不存在的原句的变更会被忽略（旧的无证据数据仍可读取）。长篇章节总结也会自动分批合并，不会截掉原始素材。
- **角色知情**：在原有角色实体中保存 `knowledge` 增量条目，包含 `fact`、`stance`（knows/suspects/believes/hides）、原文证据；仅有明确证据才能增删，不把其他角色听不到的秘密自动记作知情。当前 UI 的角色卡和注入状态会显示知情，不会额外创建 NPC。

## 时间与摘要修改

- 新生成的故事时间使用 `YYYY/MM/DD · HH:mm` 或 `YYYY/MM/DD · HH:mm–HH:mm`；只有时刻或时间未知时不虚构日期。旧记录在时间线显示时也尝试规范格式，不改写原始聊天文本。
- 摘要和分层总结卡片展开后显示**一份摘要正文**，底部有「查看原文」「编辑」「删除」按钮。点击编辑弹出独立居中窗口（L0 可编辑正文、故事时间、地点；L1+ 只编辑正文）；点击删除弹出单独的二次确认窗口，明确影响范围。按 Esc、点击外部遮罩或「取消」只关闭当前操作窗口，不关闭整个剧情记忆插件，未保存的草稿不会改动记忆。
- L0 摘要支持修改正文、故事时间与地点；L1/L2/L3+ 总结支持修改正文。修改时会使依赖旧内容的高层总结失效，但不会覆盖原始聊天。
- 删除生成的楼层摘要会同时撤销该楼层提取的物品、场景、人物、计划变化，保留原始聊天，并暂停对当前版本楼层的自动重新摘要。摘要页提供「重新摘要」入口；原剧情改变时可重新进入待摘要列表。
- 删除 L1+ 分层总结时保留下层素材，且避免同一批素材立即重复压缩。删除操作需确认。
- **恢复默认**：重置 Embedding 模型为 `BAAI/bge-m3`、重排模型为 `BAAI/bge-reranker-v2-m3`，重排开关关闭，保留向量 API 地址与密钥；摘要 API 的连接配置与模型照旧保留。

## 配置示例

附加参数 → 包含主体参数：

```text
prefix: true
```

附加参数 → 排除主体参数：

```text
frequency_penalty
presence_penalty
```

附加参数 → 包含请求标头：

```text
x-opencode-session: sillytavern
```

以上标头只是普通格式示例，不会自动填写。Authorization、Cookie 等认证标头不能手动添加；独立摘要 API 自动使用该渠道填写的 Key。为了与柏宝书一样便捷，**独立摘要 Key 会保存在 SillyTavern 扩展设置中**，请勿公开导出包含扩展设置的备份。

## 使用提示

自动摘要与自动隐藏均默认开启，但仅在成功摘要且离开保留窗口后才会隐藏旧正文。首次使用建议先在测试聊天验证副 API 响应格式、记忆注入与自动隐藏，再对长期聊天启用批量整理。

自动隐藏需要酒馆提供保存聊天的接口，实际效果仍需在目标酒馆版本测试。启用前建议先检查「注入预览」；旧聊天原文未隐藏时可能与记忆注入重复。上游内容拒绝不会通过反复重试绕过。
